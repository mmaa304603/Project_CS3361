2. Production rules

The scanner recognizes the following lexical production rules:

```
assign  -> :=
plus    -> +
minus   -> -
times   -> *
div     -> /
lparen  -> (
rparen  -> )
id      -> letter (letter | digit)*, except read and write
number  -> digit digit* | digit* ('.' digit | digit '.') digit*
comment -> '/*' (non-* | '*' non-/)* '*/'
           | '//' (non-newline)* newline
read    -> read
write   -> write
```

Comments and whitespace are skipped and do not produce tokens. The scanner
uses the longest possible valid token rule; therefore `read1` is an `id`, not
the token `read` followed by another token.

To specify a data structure for the table in Fig 2.12 in the textbook, we need the following
data structure with a name transitionTable:
(a) transitionTable is a two dimensional array. The first dimension is indexed from
1 to 18 (the number of states) and the second dimension is indexed from 1 to 14 with
1 representing white spaces (space, tab, newline), 2 representing the character /, ···,
14 representing any letter.
(b) For any integer i and j, transitionTable[i][j] is a record with field names
i. action and newState.
ii. action can take values of move, recognize,stuck.
transitionTable[i][j].action=move means that the automata should move to
next state and transitionTable[i][j].newState is the state to move to.
4
transitionTable[i][j].move = recognize means that i is a final state and the
automata can not move to any other state with the input character corresponding to
the number j, i.e., we recognize a token!
transitionTable[i][j].move = stuck means that the the automata can not get
to any state from state i with a character corresponding to the number j.
